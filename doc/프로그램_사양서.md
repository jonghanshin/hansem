## 1. 개요

### 1.1 목적
한샘 시공 현장의 계약·고객 정보(현장정보)와 현장별 입금·출금 내역(입금내역)을 한 곳에서 조회·입력·수정하고, 한샘 주문 데이터(한샘주문진도정보)를 바탕으로 정산 금액을 자동 계산하는 사내용 웹 애플리케이션이다.

### 1.2 주요 기능 요약

| 구분 | 기능 |
|---|---|
| 현장정보 | 목록 조회·검색, 신규 입력, 상세 조회·수정, 엑셀 업로드, 엑셀 내보내기, 현장별 입금내역 보기 |
| 자동 계산 | 한샘공급가합계 · 한샘물대 · 한샘시공비 · 한샘시공비외 · 환불금액을 다른 테이블에서 계산해 표시하고 테이블에 저장, 더블클릭으로 근거 내역 조회 |
| 입금내역 | 전체 목록 조회, 항목별 검색, 입금/출금 합계, 입금 등록, 엑셀 내보내기 |
| 공통 | 첫 화면 메뉴, 상단 메뉴 바, 목록 100건 단위 페이징 |

## 2. 시스템 구성

### 2.1 기술 스택

| 영역 | 사용 기술 | 버전 |
|---|---|---|
| 프레임워크 | Next.js (App Router, Cache Components, Turbopack) | 16.4.5 |
| UI | React | 19.3.0 |
| 언어 | TypeScript | 5.x |
| 스타일 | Tailwind CSS | 4.x |
| 데이터베이스 | Supabase (PostgreSQL) | 프로젝트 `npfupdxlqgylortxjwjh` |
| DB 클라이언트 | @supabase/supabase-js | 2.119.x |
| 엑셀 처리 | exceljs | 4.4.0 |
| 실행 환경 | Node.js | 24.x |

### 2.2 구조

```
브라우저 (React 클라이언트 컴포넌트)
   │  Server Action 호출 (POST)
   ▼
Next.js 서버 (Server Components / Server Actions)
   │  SUPABASE_SECRET_KEY 로 접근 (서버 전용)
   ▼
Supabase PostgreSQL ── 현장정보 / 입금내역 / 한샘주문진도정보
                        (RLS 활성화, 정책 없음 → 공개 키로는 접근 불가)
```

- 모든 DB 읽기·쓰기는 **서버에서만** secret key로 수행한다. secret key는 `server-only` 모듈(`src/lib/supabase-admin.ts`)에서만 읽으며 브라우저로 전달되지 않는다.
- 테이블은 RLS가 켜져 있고 정책이 없으므로, 브라우저에 노출되는 publishable key로는 데이터를 읽을 수 없다. 고객 개인정보(이름, 전화번호, 주소)를 보호하기 위한 구성이다.
- 목록 페이지는 요청 시점에 최신 데이터를 읽는다(`connection()` + `<Suspense>`).

## 3. 화면 사양

### 3.1 화면 목록

| 화면 | 경로 | 설명 |
|---|---|---|
| 첫 화면 | `/` | '현장정보', '입금내역' 메뉴 카드 |
| 현장정보 | `/sites` | 현장 목록 + 오른쪽 상세 패널 |
| 입금내역 | `/deposits` | 전체 입금·출금 내역 |
| 업로드 양식 | `/template` | 엑셀 업로드용 빈 양식(.xlsx) 다운로드 |

`/sites`, `/deposits` 상단에는 **홈 · 현장정보 · 입금내역** 메뉴 바가 표시되며 현재 화면이 강조된다.

### 3.2 첫 화면 (`/`)
- 제목 "현장정보 관리"와 메뉴 카드 2개(현장정보, 입금내역)를 표시한다.
- 카드를 누르면 해당 화면으로 이동한다.

### 3.3 현장정보 화면 (`/sites`)

#### 3.3.1 목록
| 항목 | 사양 |
|---|---|
| 표시 컬럼 | 상태, 현장번호, 고객명, 전화번호, 영업사원, 현장주소, 계약경로, 계약가, 공사품목, 공사시기, 계약일, 완료일 |
| 상태 | 완료일이 있으면 `완료`, 없으면 `진행` |
| 정렬 | 최근 등록 순 (id 내림차순) |
| 검색 | 검색창 1개. 현장번호·고객명·전화번호·영업사원·현장주소·계약경로·공사품목에서 포함 검색 (전화번호 `-` 무시) |
| 페이징 | 100건 단위 (3.5 참고) |
| 행 선택 | 클릭 또는 Enter/Space → 오른쪽에 상세 패널 표시, 선택 행 강조 |

#### 3.3.2 상단 버튼
| 버튼 | 동작 |
|---|---|
| 엑셀 내보내기 (N) | 현재 검색 결과 전체(모든 페이지)를 `현장정보_YYYYMMDD.xlsx`로 저장 |
| 엑셀 업로드 | 업로드 창 열기 (3.3.6) |
| + 새 현장 | 오른쪽 패널에 빈 입력 폼 열기 |

#### 3.3.3 상세 패널 (오른쪽)
- 화면 폭 1024px 이상: 목록과 상세 패널이 **50:50**으로 나란히 표시된다.
- 화면 폭 1024px 미만: 상세 패널이 목록 위에 겹쳐 표시된다.
- 상단: 고객명(없으면 현장번호), id, 등록일시, **입금내역** 버튼, 닫기 버튼.
- 입력 항목은 아래 묶음으로 표시한다.

| 묶음 | 항목 |
|---|---|
| 기본 정보 | 현장번호 *(필수)*, 고객명, 고객전화번호, 현장주소 |
| 영업 | 영업사원, 영업사원ID, 계약경로 |
| 금액 | 계약가, 상품가액, 시공비 |
| 공사 | 공사품목, 공사시기, 계약일, 완료일 |
| 한샘 정산 | 한샘공급가합계 `자동`, 한샘물대 `자동`, 한샘시공비 `자동`, 한샘추가시공비, 한샘시공비외 `자동`, 환불금액 `자동`, 정산여부, 정산월 |

- 금액 칸은 입력 후 포커스가 빠지면 천 단위 쉼표로 표시된다. 날짜 칸은 날짜 선택기를 쓴다.
- **저장** 버튼은 변경 사항이 있을 때만 활성화되고, **되돌리기**로 변경을 취소할 수 있다.
- 저장하지 않은 변경이 있는 상태에서 다른 행 선택·패널 닫기·탭 닫기를 하면 확인 창을 띄운다.
- `자동` 항목은 읽기 전용이며 4장 규칙으로 계산된다. 상세 패널을 열 때 다시 계산되고, 계산 중에는 "계산 중…"을 표시한다.

#### 3.3.4 자동 계산 항목 근거 내역
- `자동` 항목을 **더블클릭**(또는 선택 후 Enter)하면 합계의 근거 행을 팝업 목록으로 보여준다.
- 한샘공급가합계·한샘물대·한샘시공비: 확정 주문 행(주문번호, 주문등록일, 공정, 품목명, 시공일, 공급가, 공급가(HS), 공급가(S1)). 합계에 쓰인 금액 열을 강조한다.
- 한샘시공비외·환불금액: 해당 입금내역 행(날짜, 입출금, 입금자, 입금내용, 입금처, 입금액).
- 하단에 건수와 합계를 표시한다. 닫기 버튼, Esc, 바깥 영역 클릭으로 닫는다.

#### 3.3.5 상세 패널 안 입금내역 보기
- **입금내역** 버튼을 누르면 패널 내용이 해당 현장의 입금내역으로 바뀌고, 버튼은 **← 상세정보**로 바뀐다(수정 중인 입력값은 유지).
- 조회 기준은 **저장된** 현장번호이며, 현장번호가 없으면 버튼이 비활성화된다.
- 상단에 입금 합계 · 출금 합계 · 입금−출금을 표시하고, 내역을 날짜 오름차순으로 나열한다. 보기 전용이다.

#### 3.3.6 엑셀 업로드
1. .xlsx 파일 선택 (최대 5MB, 2,000행). `.xls`는 지원하지 않는다.
2. 서버가 파일을 읽어 **미리보기**를 보여준다.
   - 상단 10행 안에서 알려진 컬럼명이 2개 이상인 첫 행을 헤더로 인식한다. 공백·줄바꿈 차이는 무시한다(예: "영업사원 ID" = 영업사원ID).
   - 알 수 없는 컬럼은 "무시된 컬럼"으로 안내한다.
   - 행별 상태: `정상` / `이미 등록됨`(DB에 같은 현장번호 존재) / `파일 내 중복` / 오류 내용.
3. 오류 행은 선택할 수 없고, 중복 행은 기본으로 선택이 해제된다.
4. **선택한 N건 등록**: 선택 행을 한 번에 저장한다(전부 성공 또는 전부 실패). 저장 후 자동 계산 항목을 계산한다.
5. 업로드 파일의 자동 계산 컬럼 값은 무시한다.
6. **양식 다운로드**: `/template`에서 빈 양식을 받는다(전화번호·현장번호 열은 텍스트 서식).

### 3.4 입금내역 화면 (`/deposits`)

#### 3.4.1 목록
| 항목 | 사양 |
|---|---|
| 표시 컬럼 | 날짜, 현장번호, 고객명, 영업사원, 입출금, 금액, 입금자, 입금내용, 입금처, 입금구분, 계약가, 현금영수증, 비고 |
| 정렬 | 날짜 최신순 (날짜를 해석할 수 없는 행은 맨 뒤) |
| 합계 | 입금 합계 · 출금 합계 · 입금−출금 (현재 검색 결과 전체 기준) |
| 페이징 | 100건 단위 |

#### 3.4.2 검색
| 조건 | 방식 |
|---|---|
| 입출금 | 전체 / 입금 / 출금 버튼 |
| 현장번호, 고객명, 입금자 | 포함 검색 |
| 영업사원 | 데이터에 있는 값 드롭다운 |
| 입금구분 | 한샘·시공비·거래처환불입금 + 데이터에만 있는 값 드롭다운 |
| 날짜 | 시작일 ~ 종료일 (한쪽만 입력 가능, 기간 검색 시 날짜 해석 불가 행 제외) |
| 초기화 | 모든 조건 해제 |

조건은 입력 즉시 적용되며 여러 조건은 AND로 결합된다. 조건이 바뀌면 1페이지로 이동한다.

#### 3.4.3 입금 등록
**+ 입금 등록** 버튼으로 입력 창을 연다.

| 항목 | 필수 | 입력 방식 / 규칙 |
|---|---|---|
| 현장번호 | ✔ | 직접 입력 또는 현장 목록에서 선택. 현장정보에 있는 번호면 고객명·영업사원·계약가 자동 채움(수정 가능). 없는 번호도 등록 가능 |
| 고객명, 영업사원 | | 텍스트 |
| 계약가 | | 금액 |
| 입출금 | ✔ | 입금 / 출금 |
| 금액 | ✔ | 0보다 큰 숫자 |
| 날짜 | ✔ | 기본값 오늘 |
| 입금구분 | ✔ | **한샘 / 시공비 / 거래처환불입금** 중 선택. 입금 선택 시 기본 `한샘`, 출금 선택 시 기본 `시공비` |
| 입금자, 입금처, 현금영수증 | | 기존 값 자동완성 후보 제공, 새 값 입력 가능 |
| 입금내용, 비고 | | 텍스트 |

- 등록 후 목록·합계에 바로 반영된다.
- 입금구분이 `시공비`·`거래처환불입금`이면 해당 현장의 한샘시공비외·환불금액을 즉시 다시 계산해 저장한다.

#### 3.4.4 엑셀 내보내기
현재 검색 결과 전체(모든 페이지)를 `입금내역_YYYYMMDD.xlsx`로 저장한다. 금액은 숫자, 날짜는 엑셀 날짜로 변환한다.

### 3.5 공통: 페이징
- 목록은 한 페이지에 **100건**을 표시한다.
- 하단에 `총 N건 중 a–b`와 페이지 버튼(« ‹ 번호 › »)을 표시한다. 페이지가 많으면 처음·끝·현재 주변만 보이고 나머지는 `…`로 줄인다.
- 페이지 이동 시 목록이 맨 위로 스크롤된다.
- 페이징은 화면에서 수행하며, 서버는 전체 데이터를 1,000행 단위로 나눠 모두 읽는다(Supabase 1회 응답 최대 1,000행 제한 대응).

## 4. 업무 규칙

### 4.1 자동 계산 항목

| 현장정보 컬럼 | 원천 테이블 | 조건 | 합계 대상 |
|---|---|---|---|
| 한샘공급가합계 | 한샘주문진도정보 | `계약현장번호` = 현장번호, `주문상태` = '확정' | `공급가` |
| 한샘물대 | 한샘주문진도정보 | 위와 같음 | `공급가(HS)` |
| 한샘시공비 | 한샘주문진도정보 | 위와 같음 | `공급가(S1)` |
| 한샘시공비외 | 입금내역 | `현장번호` 일치, `입금구분` = '시공비' (입출금 무관) | `입금액` |
| 환불금액 | 입금내역 | `현장번호` 일치, `입금구분` = '거래처환불입금' | `입금액` |

- 원천 금액은 텍스트(예: `"3,928,790"`)이므로 숫자로 변환해 더한다. 숫자로 읽을 수 없는 값은 합계에서 제외하고 상세 패널에 경고를 표시한다.
- 해당 행이 없으면 0으로 저장한다.
- `임시주문`, `취소` 주문은 합계에서 제외된다.
- 계산 결과가 저장된 값과 다를 때만 테이블을 갱신한다.

**재계산 시점**

| 시점 | 대상 |
|---|---|
| 상세 패널 열기 | 해당 현장 |
| 현장 저장·신규 등록 (현장번호 변경 포함) | 해당 현장 |
| 엑셀 업로드 등록 | 등록된 현장 전체 |
| 입금 등록 (입금구분 '시공비'·'거래처환불입금') | 해당 현장번호의 현장 |

> 한샘주문진도정보나 입금내역이 앱 밖에서 바뀐 경우, 현장정보 테이블 값은 해당 현장의 상세 패널을 열 때 갱신된다.

### 4.2 현장정보 값 변환·검증 (`src/lib/sites.ts`)

| 유형 | 대상 컬럼 | 규칙 |
|---|---|---|
| 텍스트 | 현장번호, 고객명, 영업사원, 영업사원ID, 현장주소, 계약경로, 공사품목, 정산여부, 정산월 | 앞뒤 공백 제거, 빈 값은 NULL |
| 전화번호 | 고객전화번호 | 숫자만 저장. 엑셀에서 앞자리 0이 빠진 휴대폰 번호(예: `1035368885`)는 `0`을 복원. 화면에는 `010-1234-5678` 형식으로 표시 |
| 금액 | 계약가, 상품가액, 시공비, 한샘* 금액, 환불금액 | 쉼표·공백·`원`·`₩` 제거 후 정수. 숫자가 아니면 오류 |
| 날짜 | 공사시기, 계약일, 완료일 | `YYYY-MM-DD`, `YYYY.MM.DD`, `YYYY/MM/DD`, `YYYY년 M월 D일`, 엑셀 날짜·일련번호 허용. **연도 없는 날짜는 오류**, 존재하지 않는 날짜(2월 30일 등)는 오류 |
| 필수 | 현장번호 | 비어 있으면 저장 불가 |

### 4.3 입금내역 저장 형식 (`src/lib/deposits.ts`)
입금내역 테이블은 모든 컬럼이 text이므로, 기존 데이터와 같은 형식으로 저장한다.

| 항목 | 저장 형식 | 예 |
|---|---|---|
| 입금액, 계약가 | 천 단위 쉼표 문자열 | `1,480,000` |
| 날짜 | `YYYY년 MM월 DD일` | `2026년 11월 05일` |

검증 규칙: 현장번호 필수, 입출금은 입금/출금, 금액은 0보다 큰 숫자, 날짜 필수·유효, 입금구분은 한샘/시공비/거래처환불입금 중 하나.

## 6. 서버 기능

### 6.1 Server Actions (`src/app/actions.ts`)

| 함수 | 기능 |
|---|---|
| `listSitesAction()` | 현장정보 전체 조회 |
| `createSiteAction(values)` | 현장 신규 등록 → 자동 계산 |
| `updateSiteAction(id, values)` | 현장 수정 → 자동 계산 (자동 계산 컬럼은 입력값 무시) |
| `syncSiteTotalsAction(id)` | 자동 계산 항목 재계산·저장, 경고 반환 |
| `listComputedSourcesAction(현장번호, 필드)` | 자동 계산 항목의 근거 행 조회 |
| `listDepositsAction(현장번호)` | 현장별 입금내역 조회 |
| `createDepositAction(values)` | 입금 등록 (필요 시 해당 현장 재계산) |
| `parseExcelAction(formData)` | 업로드 파일 해석, 미리보기 반환 (저장하지 않음) |
| `insertSitesAction(rows)` | 업로드 선택 행 일괄 등록 → 자동 계산 |

모든 입력은 서버에서 다시 검증·변환한 뒤 저장한다. 결과는 `{ ok: true, data }` 또는 `{ ok: false, error }` 형식으로 반환한다.

### 6.2 Route Handler
| 경로 | 메서드 | 기능 |
|---|---|---|
| `/template` | GET | 엑셀 업로드 양식 다운로드 (요청 시 생성, 컬럼은 현장정보 필드 정의를 따름) |

### 6.3 주요 설정 (`next.config.ts`)
- `cacheComponents: true`, `partialPrefetching: true`
- `experimental.serverActions.bodySizeLimit: "6mb"` (엑셀 업로드 최대 5MB 수용)

## 7. 환경 설정 및 실행

### 7.1 환경 변수 (`.env.local`, git 제외)

| 변수 | 용도 | 노출 범위 |
|---|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | Supabase 프로젝트 URL | 브라우저 노출 가능 |
| `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` | 공개 키 (현재 앱에서는 미사용) | 브라우저 노출 가능 |
| `SUPABASE_SECRET_KEY` | 서버 전용 키 (RLS 우회) | **서버 전용, 절대 노출 금지** |

설정이 없으면 화면에 "`.env.local`에 NEXT_PUBLIC_SUPABASE_URL과 SUPABASE_SECRET_KEY를 설정한 뒤 개발 서버를 다시 시작하세요" 안내가 표시된다.

### 7.2 실행 명령

| 명령 | 설명 |
|---|---|
| `npm install` | 의존성 설치 |
| `npm run dev` | 개발 서버 (http://localhost:3000) |
| `npm run build` | 프로덕션 빌드 |
| `npm start` | 빌드 결과 실행 |
| `npm run lint` | 코드 검사 |

### 7.3 개발 도구 연동
Claude Code에 Supabase MCP 서버(`supabase`, 원격 HTTP)가 로컬 범위로 등록되어 있다. 대상은 위 프로젝트 하나로 제한되며 쓰기 권한이 있다. 설정은 사용자 홈의 `.claude.json`에 저장되고 저장소에는 포함되지 않는다.

## 8. 보안 및 제약 사항

| 구분 | 내용 | 권장 조치 |
|---|---|---|
| 인증 없음 | 로그인 기능이 없어, 앱에 접속할 수 있으면 누구나 고객정보를 조회·수정할 수 있다. Server Action은 POST로 직접 호출 가능하다. | 외부 배포 전 로그인·권한 확인 추가 (각 Server Action에서 검사) |
| 키 노출 이력 | 개발 중 Supabase access token과 secret key가 대화에 노출되었다. | 두 키 재발급 후 기존 키 폐기 (`.env.local`, MCP 설정 갱신) |
| 입금내역 고유키 없음 | 행을 구분할 id가 없어 개별 수정·삭제 기능을 안전하게 만들 수 없다. | 수정·삭제가 필요해지면 id(identity) 컬럼 추가 |
| 현장번호 중복 허용 | 현장번호 단독 UNIQUE 제약이 없다. 업로드 시 화면에서만 중복을 경고한다. | 필요 시 현장번호 UNIQUE 제약 추가 검토 |
| 자동 계산 시점 | 원천 데이터가 앱 밖에서 바뀌면 상세 패널을 열기 전까지 저장값이 이전 값으로 남는다. | 항상 최신이어야 하면 DB 트리거로 계산 이전 검토 |
| 대량 데이터 | 목록은 전체 데이터를 받아 화면에서 페이징한다. 수천 건까지는 문제없으나 수만 건 이상이면 느려질 수 있다. | 규모 증가 시 서버 페이징·서버 검색으로 전환 |
| 데이터 미연결 | 입금내역의 현장번호 `이천현장`은 현장정보에 없는 번호로, 어느 현장에도 표시되지 않는다. | 데이터 정리 |
| 소스 관리 | 작업 트리가 아직 git에 커밋되지 않았다. | 커밋 및 원격 저장소 연결 |
