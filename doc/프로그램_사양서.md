## 1. 개요

### 1.1 목적
한샘 시공 현장의 계약·고객 정보(현장정보)와 현장별 입금·출금 내역(입금내역)을 한 곳에서 조회·입력·수정하고, 한샘 주문 데이터(한샘주문진도정보·한샘추가시공비)를 바탕으로 현장 정산과 영업사원(RD) 정산 금액을 계산하는 사내용 웹 애플리케이션이다. 입금내역 변경은 관리자 승인을 거쳐 반영하고, 승인 진행 상황은 카카오 알림톡으로 알린다. 사내 게시판, 팀 캘린더, 거래처·공정 정보(지식자산)도 함께 관리한다.

### 1.2 주요 기능 요약

|---|---|

### 2.2 구조

```
브라우저 (React 클라이언트 컴포넌트)
   │  화면 이동 / Server Action 호출 (POST)
   ▼
proxy (src/proxy.ts) ── 세션 쿠키 서명·만료 확인 → 미로그인 시 /login 으로 이동
   ▼
Next.js 서버 (Server Components / Server Actions / Route Handlers)
   │  각 화면·액션에서 로그인·권한 재확인
   │  SUPABASE_SECRET_KEY 로 접근 (서버 전용)
   ├─▶ Supabase PostgreSQL (RLS 활성화, 정책 없음 → 공개 키로는 접근 불가)
   ├─▶ 서버 디스크 upload/ 폴더 (게시판 첨부·본문 이미지, 현장 문서, 입금 영수증)
   └─▶ SOLAPI (카카오 알림톡 발송)
```

- 모든 DB 읽기·쓰기는 **서버에서만** secret key로 수행한다. secret key는 `server-only` 모듈(`src/lib/supabase-admin.ts`)에서만 읽으며 브라우저로 전달되지 않는다.
- 테이블은 RLS가 켜져 있고 정책이 없으므로, 브라우저에 노출되는 publishable key로는 데이터를 읽을 수 없다.
- 로그인 확인은 3단계로 한다: ① proxy(화면 이동 전 빠른 확인) ② 각 화면의 `requireUser()` ③ 각 Server Action 첫 줄의 `authorizeAction()`. Server Action은 POST로 직접 호출할 수 있으므로 ③을 생략하지 않는다.
- 목록 페이지는 요청 시점에 최신 데이터를 읽는다(`connection()` + `<Suspense>`). 저장 후에는 `refresh()`로 화면 데이터를 다시 읽는다.
- 업로드 파일은 모두 `upload/` 아래에 추측할 수 없는 임의 이름으로 저장하고, 로그인·권한 확인 후 전용 경로로만 내려받는다(7.6).

## 3. 로그인 및 권한

### 3.1 사용자와 역할
사용자 계정은 `권한` 테이블에서 관리한다(관리자가 테이블에 직접 등록). 화면에서 계정을 만들거나 역할을 바꾸는 기능은 없다.

| 역할 (`권한.역할`) | 데이터 범위 | 입금 승인 | 정산 | 대시보드 | 비고 |
|---|---|---|---|---|---|
| `슈퍼관리자` | 전체 (비공개 현장 포함) | ✔ | ✔ | ✔ | |
| `CEO`, `관리자` | 전체 (비공개 현장 제외) | ✔ | ✔ | | 입금 즉시 삭제 가능 |
| `RD` (영업사원) | **본인 데이터만** (현장정보·입금내역의 `영업사원` = 본인 이름) | | | | 메뉴 바에 '내 요청' 표시 |
| 그 밖의 값 | 전체 (비공개 현장 제외) | | | | |

- RD가 저장하는 현장정보·입금내역의 `영업사원`은 항상 본인 이름으로 고정된다(화면 입력값 무시).
- 게시판·지식자산·팀 캘린더는 역할과 관계없이 모든 로그인 사용자가 같은 데이터를 본다(캘린더는 4.11의 공개 범위를 따른다).

### 3.2 비공개 현장
- `src/lib/data-scope.ts`의 `PRIVATE_SITE_NUMBERS`(현재 `1111`)에 있는 현장번호는 **해당 현장의 RD와 슈퍼관리자에게만** 보인다.
- 현장정보·입금내역·승인 요청·정산·나의정보·승인 대기 건수 조회에서 서버가 행을 제외한다(화면에서 숨기는 것이 아님).
- 1111 승인 요청 알림은 슈퍼관리자에게만 간다.

### 3.3 로그인 (`/login`)
- 영업사원ID와 비밀번호를 입력한다. ID 또는 비밀번호가 틀리면 "ID 또는 비밀번호가 올바르지 않습니다."를 표시한다.
- 같은 영업사원ID가 둘 이상 등록되어 있으면 로그인을 거부한다.
- 로그인하면 `권한.접속시간`을 기록한다.
- `권한.접속여부`가 비어 있으면 **최초 접속**으로 보고 `/change-password`로 이동한다.

### 3.4 비밀번호
| 항목 | 규칙 |
|---|---|
| 최소 길이 | 4자리 |
| 최초 변경 (`/change-password`) | 새 비밀번호 + 확인. 기존 비밀번호와 같으면 거부. 변경 시 `접속여부` = `접속` |
| 나의정보에서 변경 (`/me`) | 현재 비밀번호 확인 후 변경 |
| 저장 형식 | `권한.비번`에 **평문** 저장. 이전 버전의 `scrypt$salt$hash` 형식도 로그인 가능 |

### 3.5 세션
| 항목 | 사양 |
|---|---|
| 방식 | 쿠키 `hansem_session`에 서명된 토큰 저장 (HMAC-SHA256, 키 = `AUTH_SECRET`) |
| 내용 | 권한.id, 영업사원ID, 이름, 역할, 비밀번호 변경 필요 여부, 만료 시각 |
| 유효 시간 | 12시간 |
| 쿠키 속성 | `HttpOnly`, `SameSite=Lax`, https 접속 시 `Secure` |

- 역할·이름은 로그인 시점 값이 토큰에 들어가므로, `권한` 테이블에서 역할을 바꾸면 다시 로그인해야 반영된다.

#### 4.3.3 현장 수정 시 입금 데이터 연동
현장을 저장할 때 바뀐 값을 **같은 현장번호의 입금내역·승인필요입금내역**에도 반영한다.

| 현장에서 바뀐 값 | 함께 수정되는 항목 |
|---|---|
| 현장번호 | 해당 행 전부의 `현장번호` |
| 고객명 | 해당 행 전부의 `고객명`, `입금자`가 예전 고객명인 행의 `입금자` |
| 영업사원 | 해당 행 전부의 `영업사원` |
| 계약가 | 계약가가 입력돼 있던 행의 `계약가` |

- 다른 현장이 쓰는 현장번호로는 바꿀 수 없다.
- 한샘주문진도정보·한샘추가시공비(한샘 원본 자료)는 수정하지 않는다.
- 여러 테이블을 한 번에 묶어 처리하지 않으므로, 현장 저장 후 입금 반영이 실패하면 안내 문구를 띄운다.

#### 4.3.4 문서 파일 (최종계약서 · 최종견적서 · 자재리스트)
- 상세 패널 **영업** 묶음 아래에 문서마다 **업로드 / 변경 / 삭제**와 파일 이름(내려받기 링크)·크기·올린 날짜를 보여준다. 새 현장은 등록 후에 올릴 수 있다.
- 문서당 파일 1개, 20MB 이하, 실행 파일 형식 금지. 다시 올리면 이전 파일은 지운다.
- 실제 파일: `upload/contract`, `upload/estimate`, `upload/material`. 내려받기 정보는 현장정보의 `최종계약서`·`최종견적서`·`자재리스트` 컬럼에 JSON(원래 이름·저장 이름·크기·올린 시각)으로 저장한다.
- 그 현장을 볼 수 있는 사용자만 올리고 내려받을 수 있다.

#### 4.3.5 상세 패널 안 입금내역 보기
- **입금내역** 버튼으로 해당 현장의 입금내역과 **계약 금액 대비 입금·출금** 표(시공비·한샘·홈씨씨·계약가 합계별 계약/입금/미입금/출금)를 보여준다. 묶음 규칙은 `src/lib/site-money.ts`(대시보드와 동일).

#### 4.3.6 엑셀 업로드
1. .xlsx 파일 선택 (최대 5MB, 2,000행). 상단 10행 안에서 알려진 컬럼명이 2개 이상인 첫 행을 헤더로 인식한다.
2. 미리보기 행 상태: `정상` / `이미 등록됨` / `파일 내 중복` / 오류 내용.
3. **오류 행과 현장번호 중복 행은 선택할 수 없다**(등록 불가). 서버에서도 파일 안 중복·이미 등록된 번호를 거부한다.
4. 선택 행을 한 번에 저장(전부 성공 또는 전부 실패)하고 자동 계산 항목을 계산한다. 자동 계산 컬럼 값은 무시한다.
5. **양식 다운로드**: `/template`.

#### 4.4.4 거래처 선택 팝업
1. 공정표의 `공정`을 `순서`대로 보여주고, 고른 공정의 공정별거래처를 카드로 보여준다. 맨 아래 **직접 입력**.
2. 거래처를 고르면 공정·세부공정·업체·업체담당자·연락처·업체비고와 계좌를 보여준다. 담당자·연락처·계좌는 입력·수정 가능(원본은 바뀌지 않음).
3. 계좌는 **업체계좌 / 대체계좌** 중 하나를 고른다. 고르지 않은 쪽 계좌는 비운 채 저장한다.

| 화면 이름 | 저장 컬럼 (입금내역) |
|---|---|
| 공정 / 세부공정 / 업체 | 공정 / 주요작업 / 업체 |
| 업체담당자 이름 / 연락처 / 업체비고 | 업체담당자성함 / 업체담당자연락처 / 업체비고 |
| 업체계좌 은행 / 예금주 / 번호 | 업체은행 / 업체예금주 / 업체계좌번호 |
| 대체계좌 은행 / 예금주 / 번호 | 대체계좌 은행 / 대체계좌 예금주 / 대체계좌 번호 |

#### 4.4.5 입금 삭제·엑셀 내보내기
- 승인 권한자는 확인 후 **즉시 삭제**한다. 한샘 외 시공비·거래처환불이면 해당 현장의 자동 계산 항목을 다시 계산한다.
- 엑셀 내보내기: 현재 검색 결과 전체를 `입금내역_YYYYMMDD.xlsx`로 저장한다.

### 4.5 입금 승인 절차

```
[요청자] 등록·수정 요청 ──▶ 승인대기 ──(승인)──▶ 승인 : 입금내역에 반영 + 자동 계산
           │                   │  ▲
           │      (확인사항요청)│  │(의견 등록)       ※ 승인대기 상태 유지
           │                   ▼  │
           │              관리자 ↔ 요청자 의견
           │                   │
(승인취소요청: 요청 삭제)◀──┤  (반려 + 의견)
                               ▼
                              반려 ──(고쳐서 다시 요청)──▶ 승인대기
                               └──(요청자가 삭제)──▶ 요청 행 삭제
```

| 요청구분 | 승인 시 처리 |
|---|---|
| 등록 | 입금내역에 새 행 입력 |
| 수정 | `입금내역id` 행을 요청 내용으로 변경 |
| 삭제 | `입금내역id` 행 삭제 (기존 요청만 해당, 새 삭제 요청은 만들어지지 않음) |

- 승인 후 요청 내용과 변경 전 값 양쪽 현장의 자동 계산 항목을 다시 계산한다.
- 이미 처리된 요청을 다시 승인·반려·취소하면 거부한다.

#### 4.5.1 입금 승인 화면 (`/approvals`, 승인 권한자)
- 승인 대기 요청을 카드로 나열한다: 요청구분, 요청자, 요청일시, 요청 내용(수정은 바뀌는 항목만 이전 → 이후), 부가세 포함, 영수증 파일 링크. 거래처·계좌 정보는 **출금일 때만** 표시한다.
- 버튼: **확인사항요청** / **반려**(의견 필수, 500자) / **승인**(확인 창).
- 확인사항요청: 의견을 남기면 요청은 승인대기로 남고, 카드에 관리자 확인사항과 요청자 답변이 시간 순서로 표시된다. 마지막 의견이 관리자 것이면 `확인사항 요청`, 요청자 것이면 `요청자 답변` 표시가 붙는다.

#### 4.5.2 내 승인 요청 화면 (`/my-requests`)
- 승인대기 건: 관리자 확인사항을 보고 **의견 등록**(답변, 확인사항이 있을 때) 또는 **승인취소요청**(확인 후 요청 삭제, 입금내역 변화 없음).
- 반려 건: 반려 사유를 보고 **수정 후 다시 요청** 또는 **삭제**.
- 의견은 본인 요청에만 남길 수 있다. 관리자는 볼 수 있는 요청에만 의견을 남길 수 있다(비공개 현장은 슈퍼관리자만).

### 4.6 카카오 알림톡
SOLAPI로 승인된 템플릿 `입금 관련 알림` 하나를 쓴다. 변수: `#{임직원}`(받는 사람 이름), `#{고객명}`, `#{RD}`(영업사원), `#{현장번호}`, `#{금액}`, `#{입금구분}`(→ **고객명 + 입금구분 + 상태**, 예: `홍길동 나비계약금 승인요청`).

| 시점 | 상태 | 받는 사람 |
|---|---|---|
| 입금 등록·수정 요청, 반려 후 재요청 | 승인요청 | 승인 권한자 (요청자 본인 제외, 비공개 현장은 슈퍼관리자만) |
| 승인 | 승인 | 역할이 RD이고 이름이 입금의 영업사원과 같은 계정 |
| 반려 | 반려 | 위와 같음 |
| 관리자 확인사항요청 | 확인사항요청 | 그 승인 요청을 한 사람 |
| 요청자 의견 등록 | 확인사항답변 | 승인 권한자 (작성자 본인 제외, 비공개 현장은 슈퍼관리자만) |

- 받는 사람의 전화번호는 `권한.전화번호`. 번호가 없으면 건너뛴다. 알림톡 실패 시 문자로 대체 발송한다.
- 발송이 실패해도 입금 처리는 그대로 진행되며 오류는 서버 로그에만 남는다.
- `SOLAPI_TEST_RECIPIENT`가 설정되어 있으면 모든 알림을 그 번호로만 보낸다(개발용).
- 입금 즉시 삭제, 승인취소요청, 반려 건 삭제는 알림을 보내지 않는다.

### 4.7 정산 화면 (`/settlement`, CEO·관리자·슈퍼관리자)

#### 4.7.1 대상 선택
- 대상: 정산여부가 **미정산**이고 현장번호가 있는 현장.
- 필터: 영업사원(전체 또는 1명), **정산월(필수, '전체' 없음)**. 정산월 기본값은 이번 달이 목록에 있으면 이번 달, 없으면 첫 번째 월. 정산월이 비어 있는 현장은 정산 목록에 나오지 않는다.
- 목록: 현장번호, 고객명, 영업사원, 정산월, 계약금, 한샘상품가액, 홈씨씨상품가액, 시공비. 여러 개를 골라 **정산**을 누른다(한 번에 200개까지).

#### 4.7.2 정산대상 표
| 컬럼 | 값 |
|---|---|
| 계약금 | 현장정보.계약가 |
| 총입금액 | 입금내역 중 입금 합계 (거래처환불 포함). **상세**: 입금구분별 합계 → 펼치면 개별 내역 |
| 총출금액 합계 | 아래 컬럼의 합 |
| 한샘(부가세포함) | 한샘주문진도정보 **확정 주문**의 공급가 × 1.1(주문별 반올림) + 한샘추가시공비 테이블 합계 |
| 홈씨씨(부가세포함) | 입금내역 출금 중 홈씨씨창호 |
| 시공비(한샘외) 부가세포함 / 부가세미포함 | 입금내역 출금 중 한샘 외 시공비를 `부가세포함` 값으로 나눔 (비어 있으면 포함) |
| 기타 | 위에 속하지 않는 출금이 있을 때만 표시 |

- 한샘 **상세**: 공급가·공급가(HS)·공급가(S1)와 각각의 부가세포함 금액, 공급가 소계, 추가시공비(상세를 누르면 한샘추가시공비 행 목록), 한샘(부가세포함) 합계.
- 한샘추가시공비는 `현장코드` = 현장번호인 행의 `시공비`를 모두 더한다. 숫자가 아닌 금액은 합계에서 빼고 경고로 표시한다.

#### 4.7.3 정산결과 표
| 컬럼 | 값 |
|---|---|
| 계약금(부가세제외) | 계약금 ÷ 1.1 (원 단위 반올림) |
| 한샘·홈씨씨·시공비(한샘외)(부가세제외) | 정산대상 표의 부가세포함 금액 ÷ 1.1. 부가세미포함·기타는 그대로 |
| 총출금액 합계 | 이 표에 보이는 컬럼의 합 |
| 이익금액 | 계약금(부가세제외) − 총출금액 합계 (계약금이 없으면 `-`) |

한샘(부가세제외) 상세는 부가세포함 칸을 빼고 보여준다.

#### 4.7.4 RD 정산금액
```
정산대상금액 = 이익금액 합계 − 공제금(2,500,000원) − 전달 누적이월금
```
- 정산대상금액이 **0 이상**이면 **정산금액** = 구간별 누진 계산(근로자 몫), 누적이월금은 0.
- **음수**이면 정산금액 0, **이월금액** = 그 금액(양수로 표시) = 이번 달 누적이월금.
- 구간별 근로자 비율은 **영업사원 개인별로 `권한` 테이블**에서 읽는다.

| 구간 | `권한` 컬럼 | 기본값 |
|---|---|---|
| 500만원 이하 | `500이하` | 30% |
| 500만원 초과 ~ 1,000만원 이하 | `1000이하` | 35% |
| 1,000만원 초과분 | `1000초과` | 40% |

  예: 정산대상금액 800만원, 비율 30·35% → 500만원×30% + 300만원×35% = 255만원 (원 단위 반올림). 값이 비었거나 숫자가 아니면 그 구간은 기본값을 쓴다.
- **전달 누적이월금**: 같은 영업사원의 전달 정산정보 기록. 단 `권한.초기화여부`가 `Y`인 영업사원은 `권한.정산시작월` 기준 3개월째 되는 달(예: 1월 시작 → 1·4·7·10월)에 0으로 리셋한다.
- 개인 비율·누적이월금은 **영업사원과 정산월이 각각 하나**일 때만 적용된다. 표 아래에 계산식과 그 사람의 비율로 만든 정산 공식을 표시한다.

#### 4.7.5 정산결과 저장·조회
- **정산결과 저장**: 영업사원·정산월이 하나씩일 때만 가능. 서버에서 같은 식으로 다시 계산해 `정산정보`에 저장한다.
- 정산월은 연도를 붙여 `YYYY-MM`으로 저장한다(오늘에서 가장 가까운 해). 같은 영업사원·같은 `YYYY-MM` 기록이 있으면 고쳐 쓴다.
- 저장해도 현장의 정산여부는 바뀌지 않는다.
- **정산결과** 버튼: 저장된 정산정보를 영업사원·정산월(각각 전체 가능)로 골라 본다. 정산월, 영업사원, 총이익금, 정산금, 이월금, 누적이월금, 저장일시와 합계.

#### 4.7.6 한샘 데이터 업로드 (오른쪽 위 버튼)
| 버튼 | 대상 테이블 |
|---|---|
| 한샘주문진도정보 | `한샘주문진도정보` |
| 한샘추가시공비 | `한샘추가시공비` |

- 파일: `.csv`(UTF-8 또는 EUC-KR) 또는 `.xlsx`(첫 번째 시트), 10MB 이하. **기존 데이터 뒤에 추가**한다(같은 파일을 다시 올리면 중복).
- 첫 행 컬럼명이 테이블과 정확히 같아야 한다. 컬럼명 행이 없고 컬럼 수가 같으면 테이블 순서대로 읽는다. 한샘주문진도정보의 `거래처` 컬럼은 `대리점`으로 받는다.
- 정수 컬럼은 쉼표를 지우고 정수만 허용, 금액 컬럼(공급가 등·시공비)은 `101,400` 형식으로 맞춘다. 엑셀 날짜 셀은 `YYYY-MM-DD`.
- 한 건이라도 오류가 있으면 아무것도 넣지 않고 행·컬럼별 오류를 보여준다.
- **전체 데이터 삭제**: 현재 건수와 경고를 보여준 뒤 확인하면 테이블의 모든 행을 지운다.

### 4.8 나의정보 화면 (`/me`)
| 영역 | 내용 |
|---|---|
| 내 정보 | 영업사원ID, 이름, 역할, 최근 로그인, 승인 권한 |
| 비밀번호 변경 | 현재 비밀번호 + 새 비밀번호 + 확인 |

| 내 요청 / 진행 중인 현장 | 승인 대기·반려 건수, 최근 계약일 순 10건 |

### 4.9 게시판 (`/board`)

#### 4.9.1 목록
| 항목 | 사양 |
|---|---|
| 카테고리 탭 | **전체 / 견적 / 계약 / 교육** (`?cat=`). 카테고리 없는 글은 '전체'에서만 보인다 |
| 표시 컬럼 | 번호, 카테고리 배지 + 제목(첨부 개수), 작성자, 작성일, 조회 |
| 공지 | 검색·페이지와 관계없이 위에 고정. 카테고리 화면에는 그 카테고리 공지와 카테고리 없는 공통 공지 |
| 검색 | 제목+내용 / 제목 / 작성자, 서버 검색 |
| 페이징 | 15건 단위 |

#### 4.9.2 글쓰기·수정
- 카테고리 선택(없음 / 견적 / 계약 / 교육). 카테고리 화면에서 글쓰기를 누르면 그 카테고리가 미리 선택된다.
- **서식 편집기**(Tiptap): 큰·작은 제목, 굵게, 기울임, 밑줄, 취소선, 글자색, 형광펜, 왼쪽·가운데·오른쪽 정렬, 글머리·번호 목록, 인용, 구분선, 링크, 표 넣기, 이미지 넣기, 실행 취소·다시 실행.
- 본문 이미지: PNG·JPG·GIF·WEBP, 10MB 이하. `upload/board-images`에 저장하고 `/board/images/[name]`으로 보여준다. 글을 지우면 본문 이미지도 지운다.
- 저장 형식: 서식 있는 글은 HTML(`서식` = true)로 저장하고, 저장할 때와 화면에 그릴 때 허용된 태그·스타일만 남긴다(스크립트·이벤트 속성·외부 이미지 제거). 예전 글(`서식` = false)은 일반 텍스트로 표시한다.
- 권한: 글쓰기는 전체, 수정·삭제는 작성자 또는 승인 권한자, 공지 지정은 승인 권한자.
- 첨부파일: 파일 10MB, 한 번에 20MB, 글당 10개, 실행 파일 확장자 금지. `upload/`에 저장, `/board/files/[fileId]`로 내려받기.
- 글을 열면 조회수를 1 올린다(본인 글 제외).

### 4.10 팀 캘린더 (`/calendar`)
- 월 달력(일요일 시작). 이전 달 / 다음 달 / 오늘 이동, 주소 `?ym=YYYY-MM`.
- **팀원 선택**: 다른 팀원(최대 20명)을 골라 일정을 함께 본다(`?users=3,5`). 팀원은 `권한` 테이블 사용자.
- 일정 구분: **개인**(본인과 함께 보기로 고른 사람에게 보임) / **공용**(모든 사람에게 보임, 검은색 표시).
- 색상: 본인 파랑, 팀원은 팀원 목록 순서로 정해진 색. 개인 일정은 직접 색을 고를 수 있다(11색).
- 날짜 칸 한 번 누르기 → 새 일정, 일정 누르기 → 일정 보기, **두 번 누르기(더블클릭·더블탭) → 그날 일정 전체 목록**(제목 전체, 메모 2줄).
- 일정 항목: 제목(100자), 메모(2,000자), 시작일·종료일, 시작·종료시간(없으면 종일), 구분, 색상.
- 하루 안 정렬: 공용 → 종일·여러 날 → 시작시간 순.
- 일정은 로그인한 본인 것으로 등록되고, 수정·삭제는 등록한 본인만 할 수 있다(공용 일정 포함).

### 4.11 지식자산 (`/knowledge`)
| 탭 | 테이블 |
|---|---|
| 공정별거래처 (기본) | 공정별거래처 |
| 타공정거래처 | 타공정거래처 |
| 공정표 | 공정표 (순서 오름차순) |

- 검색(모든 컬럼, 여러 단어 AND), 공정 필터, 행 클릭으로 수정 창, **+ 추가**.
- **삭제**: 경고 확인 후 즉시 삭제(되돌릴 수 없음, 승인 절차 없음).
- **엑셀 내보내기**: 현재 탭의 검색 결과를 엑셀로 저장.
- 로그인한 모든 사용자가 조회·추가·수정·삭제할 수 있다.

### 4.12 대시보드 (`/dashboard`, 슈퍼관리자)
- 대상: 진행 중인 현장(완료일 없음). 가로 = 시공비 · 한샘 · 홈씨씨 · 합계, 세로 = 현장마다 계약금 · 입금 · 출금 · 미입금.
- 맨 아래 합산(화면 아래 고정): 계약금 · 입금 · 출금 · 미입금 합계, **예상공사비** = 합산 계약금 × 비율(항목별 입력, 기본 85%), **통장잔고**(화면 입력, 저장 안 함), **미입금 + 통장잔고 − (예상공사비 − 출금)**. 마지막 줄의 미입금·출금은 해당 항목의 계약금이 있는 현장만 더한다.

### 4.13 공통
- DB 조회 실패는 빨간 안내 상자, Server Action 실패는 해당 창 하단에 오류 문구로 표시한다.
- 현장정보·입금내역 목록은 한 페이지 100건, 서버는 전체를 1,000행 단위로 나눠 읽는다.

## 7. 서버 기능

모든 Server Action은 첫 줄에서 `authorizeAction()`으로 로그인을 확인하고, 입력을 서버에서 다시 검증한다. 결과는 `{ ok: true, data }` 또는 `{ ok: false, error }`.

### 7.1 현장정보·입금·승인 (`src/app/actions.ts`)
| 함수 | 권한 | 기능 |
|---|---|---|
| `createSiteAction` / `updateSiteAction` | 전체 (범위 적용) | 현장 등록·수정 (현장번호 중복 검사, 수정 시 입금 데이터 연동) → 자동 계산 |

### 8.2 실행 명령
| 명령 | 설명 |
|---|---|
| `npm run dev` / `npm run build` / `npm start` / `npm run lint` | 개발 서버 / 빌드 / 실행 / 코드 검사 |

### 8.3 배포 시 확인 사항
- 환경 변수를 호스팅 환경에 설정한다(SOLAPI 포함, 테스트 수신 번호 제외). SOLAPI 잔액을 충전한다.
- 업로드 파일(게시판 첨부·본문 이미지, 현장 문서, 영수증)은 서버 디스크 `upload/`에 저장되므로 **디스크가 유지되는 서버**에서 실행하고 백업 대상에 포함한다. 개발 PC와 운영 서버의 파일은 서로 공유되지 않는다.
- `doc/`의 DB 변경 스크립트(6.10)가 운영 DB에 모두 적용되었는지 확인한다.
- 개발 서버와 운영 서버가 같은 DB를 쓰므로, 개발 중 테스트 데이터가 운영 데이터에 남는다.

## 9. 보안 및 제약 사항

| 구분 | 내용 | 권장 조치 |
|---|---|---|
| 비밀번호 평문 저장 | `권한.비번` 평문, 로그인 실패 횟수 제한 없음 | 해시 저장 전환, 시도 제한 |
| 키 노출 이력 | 개발 중 Supabase 키, SOLAPI API Secret이 대화에 노출됨 | 재발급 후 기존 키 폐기 |
| 지식자산 수정 권한 | 모든 사용자가 거래처 계좌를 수정·삭제 가능, 이력 없음 | 권한 제한·이력 검토 |
| 관리자 즉시 삭제 | 입금 즉시 삭제·한샘 데이터 전체 삭제는 되돌릴 수 없음 | 삭제 이력·백업 |
| 비공개 현장 | 현장번호 `1111`이 코드에 고정. 직접 입력하면 다른 사용자도 그 번호로 입금·현장을 등록할 수 있다 | 필요 시 입력 차단, 설정 테이블로 이전 |
| 현장번호 중복 | 앱에서 막지만 동시 저장은 DB 제약이 있어야 막힌다 | `현장정보_현장번호_유니크.sql` 적용 |
| 정산월 연도 | 현장정보 정산월에 연도가 없어 저장 시 가장 가까운 해를 붙인다 | 정산월을 `YYYY-MM`으로 입력하도록 변경 검토 |
| 누적이월금 재계산 | 지난달을 다시 저장해도 다음 달 값은 자동으로 다시 계산되지 않는다 | 다음 달도 다시 저장 |
| 한샘 데이터 업로드 | 추가만 하므로 같은 파일을 다시 올리면 중복되어 정산 금액이 커진다 | 업로드 전 기간 확인, 필요 시 전체 삭제 후 재업로드 |
| 업로드 파일 | 서버 디스크 저장, 고아 파일(업로드 후 요청하지 않은 영수증 등)이 남을 수 있음 | 백업, Supabase Storage 이전·정리 작업 검토 |
| 알림톡 | 템플릿 하나라 첫 문장이 고정, 의견 내용은 보내지 않음 | 용도별 템플릿 추가 검수 |
| 이전 입금구분 데이터 | 0.1 형식 행은 자동 계산에 포함되지 않음 | 일괄 변경 |
| 대량 데이터 | 현장정보·입금내역은 전체를 받아 화면에서 페이징 | 규모 증가 시 서버 페이징 |
