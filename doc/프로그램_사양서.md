## 1. 개요

### 1.1 목적
한샘 시공 현장의 계약·고객 정보(현장정보)와 현장별 입금·출금 내역(입금내역)을 한 곳에서 조회·입력·수정하고, 한샘 주문 데이터(한샘주문진도정보)를 바탕으로 정산 금액을 자동 계산하는 사내용 웹 애플리케이션이다. 입금내역 변경은 관리자 승인을 거쳐 반영하며, 사내 게시판과 거래처·공정 정보(지식자산)도 함께 관리한다.

### 1.2 주요 기능 요약

| 구분 | 기능 |
|---|---|
| 로그인·권한 | 영업사원ID·비밀번호 로그인, 최초 접속 시 비밀번호 변경 강제, 역할별 데이터 범위(RD는 본인 데이터만), 승인 권한(CEO·관리자) |
| 현장정보 | 목록 조회·검색, 신규 입력, 상세 조회·수정, 엑셀 업로드, 엑셀 내보내기, 현장별 입금내역 보기 |
| 자동 계산 | 한샘공급가합계 · 한샘물대 · 한샘시공비 · 한샘시공비외 · 환불금액을 다른 테이블에서 계산해 표시·저장, 더블클릭으로 근거 내역 조회 |
| 입금내역 | 전체 목록 조회, 항목별 검색, 입금/출금 합계, 입금 등록·수정 **승인 요청**, 관리자 삭제, 엑셀 내보내기 |

### 2.1 기술 스택

| 영역 | 사용 기술 | 버전 |
|---|---|---|
| 프레임워크 | Next.js (App Router, Cache Components, Partial Prefetching, Turbopack) | 16.4.5 |
| UI | React | 19.3.0 |
| 언어 | TypeScript | 5.x |
| 스타일 | Tailwind CSS | 4.x |
| 데이터베이스 | Supabase (PostgreSQL) | 프로젝트 `npfupdxlqgylortxjwjh` |
| DB 클라이언트 | @supabase/supabase-js | 2.119.x |

| 실행 환경 | Node.js | 24.x |

### 2.2 구조

```
브라우저 (React 클라이언트 컴포넌트)
   │  화면 이동 / Server Action 호출 (POST)
   ▼
proxy (src/proxy.ts) ── 세션 쿠키 서명·만료 확인 → 미로그인 시 /login 으로 이동
   ▼
Next.js 서버 (Server Components / Server Actions / Route Handlers)
   │  각 화면·액션에서 로그인·권한 재확인
   │  SUPABASE_SECRET_KEY 로 접근 (서버 전용)
   ├─▶ Supabase PostgreSQL (RLS 활성화, 정책 없음 → 공개 키로는 접근 불가)
   └─▶ 서버 디스크 upload/ 폴더 (게시판 첨부파일)
```

- 모든 DB 읽기·쓰기는 **서버에서만** secret key로 수행한다. secret key는 `server-only` 모듈(`src/lib/supabase-admin.ts`)에서만 읽으며 브라우저로 전달되지 않는다.
- 테이블은 RLS가 켜져 있고 정책이 없으므로, 브라우저에 노출되는 publishable key로는 데이터를 읽을 수 없다.
- 로그인 확인은 3단계로 한다: ① proxy(화면 이동 전 빠른 확인) ② 각 화면의 `requireUser()` ③ 각 Server Action 첫 줄의 `authorizeAction()`. Server Action은 POST로 직접 호출할 수 있으므로 ③을 생략하지 않는다.
- 목록 페이지는 요청 시점에 최신 데이터를 읽는다(`connection()` + `<Suspense>`). 저장 후에는 `refresh()`로 화면 데이터를 다시 읽는다.

## 3. 로그인 및 권한

### 3.1 사용자와 역할
사용자 계정은 `권한` 테이블에서 관리한다(관리자가 테이블에 직접 등록). 화면에서 계정을 만들거나 역할을 바꾸는 기능은 없다.

| 역할 (`권한.역할`) | 데이터 범위 | 입금 승인 | 입금 삭제 | 비고 |
|---|---|---|---|---|
| `CEO`, `관리자` | 전체 | ✔ | ✔ (승인 없이 즉시) | 메뉴 바에 '입금 승인' 표시 |
| `RD` (영업사원) | **본인 데이터만** (현장정보·입금내역의 `영업사원` = 본인 이름) | | | 메뉴 바에 '내 요청' 표시 |
| 그 밖의 값 | 전체 | | | |

- RD가 저장하는 현장정보·입금내역의 `영업사원`은 항상 본인 이름으로 고정된다(화면 입력값 무시).
- 게시판·지식자산은 역할과 관계없이 모든 로그인 사용자가 같은 데이터를 본다.

### 3.2 로그인 (`/login`)
- 영업사원ID와 비밀번호를 입력한다. ID 또는 비밀번호가 틀리면 "ID 또는 비밀번호가 올바르지 않습니다."를 표시한다(어느 쪽이 틀렸는지 알려 주지 않음).
- 같은 영업사원ID가 둘 이상 등록되어 있으면 로그인을 거부한다.
- 로그인하면 `권한.접속시간`을 기록한다.
- `권한.접속여부`가 비어 있으면 **최초 접속**으로 보고 `/change-password`로 이동한다. 비밀번호를 바꾸기 전에는 다른 화면을 쓸 수 없다.
- 이미 로그인한 상태로 `/login`에 들어오면 첫 화면으로 이동한다.

### 3.3 비밀번호
| 항목 | 규칙 |
|---|---|
| 최소 길이 | 4자리 |
| 최초 변경 (`/change-password`) | 새 비밀번호 + 확인. 기존 비밀번호와 같으면 거부. 변경 시 `접속여부` = `접속` |
| 나의정보에서 변경 (`/me`) | 현재 비밀번호 확인 후 변경. 현재 비밀번호와 같으면 거부 |
| 저장 형식 | `권한.비번`에 **평문** 저장 (관리자가 테이블에서 직접 확인·초기화하기 위함). 이전 버전의 `scrypt$salt$hash` 형식도 로그인 가능 |

### 3.4 세션
| 항목 | 사양 |
|---|---|
| 방식 | 쿠키 `hansem_session`에 서명된 토큰 저장 (HMAC-SHA256, 키 = `AUTH_SECRET`) |
| 내용 | 권한.id, 영업사원ID, 이름, 역할, 비밀번호 변경 필요 여부, 만료 시각 |
| 유효 시간 | 12시간 |
| 쿠키 속성 | `HttpOnly`, `SameSite=Lax`, https로 접속한 경우에만 `Secure` |
| 로그아웃 | 쿠키 삭제 후 로그인 화면으로 이동 |

- 역할·이름은 로그인 시점 값이 토큰에 들어가므로, `권한` 테이블에서 역할을 바꾸면 다시 로그인해야 반영된다.

## 4. 화면 사양

### 4.1 화면 목록

| 화면 | 경로 | 대상 | 설명 |
|---|---|---|---|
| 로그인 | `/login` | 미로그인 | 영업사원ID·비밀번호 입력 |
| 비밀번호 변경 | `/change-password` | 최초 접속 | 새 비밀번호 설정 |
| 첫 화면 | `/` | 전체 | 메뉴 카드, 승인 알림 배너 |
| 현장정보 | `/sites` | 전체 | 현장 목록 + 오른쪽 상세 패널 |
| 입금내역 | `/deposits` | 전체 | 입금·출금 내역, 등록·수정 요청 |
| 입금 승인 | `/approvals` | CEO·관리자 | 승인 대기 요청 승인/반려 (그 외 역할은 첫 화면으로 이동) |
| 내 승인 요청 | `/my-requests` | 전체 | 내가 요청한 대기·반려 건 |
| 나의정보 | `/me` | 전체 | 계정 정보, 비밀번호 변경, 내 현장·입금 요약 |

| 대시보드 | `/dashboard` | CEO·관리자 (그 외는 `/`로 이동) | 진행 중 현장의 계약금·입금·출금 |

### 4.2 첫 화면 (`/`)

  - 그 외: 반려된 내 요청 또는 대기 중인 내 요청이 있으면 해당 안내 → `/my-requests`

### 4.3 상단 메뉴 바 (공통)
- **홈 · 현장정보 · 입금내역 · 게시판 · 지식자산**(+ CEO·관리자는 **대시보드**), 현재 화면 강조.

#### 4.4.3 상세 패널 (오른쪽)
- 화면 폭 1024px 이상: 목록과 상세 패널이 **50:50**으로 나란히 표시된다.
- 화면 폭 1024px 미만: 상세 패널이 목록 위에 겹쳐 표시된다.
- 상단: 고객명(없으면 현장번호), id, 등록일시, **입금내역** 버튼, 닫기 버튼.
- 입력 항목은 아래 묶음으로 표시한다.

| 묶음 | 항목 |
|---|---|
| 기본 정보 | 현장번호 *(필수)*, 고객명 *(신규 필수)*, 고객전화번호, 현장주소 |
| 영업 | 영업사원, 영업사원ID, 계약경로 |
| 금액 | 계약가, 시공비, 한샘(한샘상품가액), 홈씨씨(홈씨씨상품가액). 화면 이름은 "한샘"·"홈씨씨". **시공비 + 한샘 + 홈씨씨 = 계약가**여야 저장된다(빈 칸은 0, 네 칸 모두 비면 검사 안 함). 칸 아래에 합계와 차이를 바로 보여준다. 서버(새 현장·수정)에서도 같은 검사. 엑셀 업로드는 검사하지 않음 |
| 공사 | 공사품목, 공사시기, 계약일, 완료예정일, 완료일 |
| 한샘 정산 | 한샘공급가합계 `자동`, 한샘물대 `자동`, 한샘시공비 `자동`, 한샘추가시공비, 한샘시공비외 `자동`, 환불금액 `자동`, 정산여부, 정산월 |

- **새 현장 등록 시 영업사원·영업사원ID는 로그인한 사용자의 영업사원ID로 `권한` 테이블을 찾아 자동으로 채운다**(화면 입력값은 쓰지 않음). 권한 테이블에 해당 ID나 이름이 없으면 등록할 수 없다.
- 금액 칸은 입력 후 포커스가 빠지면 천 단위 쉼표로 표시된다. 날짜 칸은 날짜 선택기를 쓴다.
- **저장** 버튼은 변경 사항이 있을 때만 활성화되고, **되돌리기**로 변경을 취소할 수 있다.
- 저장하지 않은 변경이 있는 상태에서 다른 행 선택·패널 닫기·탭 닫기를 하면 확인 창을 띄운다.
- `자동` 항목은 읽기 전용이며 5.1 규칙으로 계산된다. 상세 패널을 열 때 다시 계산되고, 계산 중에는 "계산 중…"을 표시한다.
- 현장 삭제 기능은 없다.

#### 4.4.4 자동 계산 항목 근거 내역
- `자동` 항목을 **더블클릭**(또는 선택 후 Enter)하면 합계의 근거 행을 팝업 목록으로 보여준다.
- 한샘공급가합계·한샘물대·한샘시공비: 확정 주문 행(주문번호, 주문등록일, 공정, 품목명, 시공일, 공급가, 공급가(HS), 공급가(S1)). 합계에 쓰인 금액 열을 강조한다.
- 한샘시공비외·환불금액: 해당 입금내역 행(날짜, 입출금, 입금자, 입금내용, 입금처, 입금액).
- 하단에 건수와 합계를 표시한다. 닫기 버튼, Esc, 바깥 영역 클릭으로 닫는다.

#### 4.4.5 상세 패널 안 입금내역 보기
- **입금내역** 버튼을 누르면 패널 내용이 해당 현장의 입금내역으로 바뀌고, 버튼은 **← 상세정보**로 바뀐다(수정 중인 입력값은 유지).
- 조회 기준은 **저장된** 현장번호이며, 현장번호가 없으면 버튼이 비활성화된다.
- 맨 위에 **계약 금액 대비 입금·출금** 표: 항목(시공비 · 한샘 · 홈씨씨 · 계약가 합계)별 계약(현장정보 저장값), 입금, 미입금(계약−입금, 넘으면 "초과"), 출금. 입금구분으로 묶는다 — 시공비 = 계약금1·2·착수금1·2·중도금1~3·잔금1·2(입금)와 한샘 외 시공비(출금), 한샘 = 한샘물대·한샘시공비, 홈씨씨 = 홈씨씨창호(입금/출금 모두). 거래처환불·예전 형식 구분은 넣지 않는다.
- 그 아래에 입금 합계 · 출금 합계를 표시하고, 내역을 날짜 오름차순으로 나열한다. 보기 전용이다.

#### 4.4.6 엑셀 업로드
1. .xlsx 파일 선택 (최대 5MB, 2,000행). `.xls`는 지원하지 않는다.
2. 서버가 파일을 읽어 **미리보기**를 보여준다.
   - 상단 10행 안에서 알려진 컬럼명이 2개 이상인 첫 행을 헤더로 인식한다. 공백·줄바꿈 차이는 무시한다(예: "영업사원 ID" = 영업사원ID).
   - 알 수 없는 컬럼은 "무시된 컬럼"으로 안내한다.
   - 행별 상태: `정상` / `이미 등록됨`(DB에 같은 현장번호 존재) / `파일 내 중복` / 오류 내용.
3. 오류 행은 선택할 수 없고, 중복 행은 기본으로 선택이 해제된다.
4. **선택한 N건 등록**: 선택 행을 한 번에 저장한다(전부 성공 또는 전부 실패). 저장 후 자동 계산 항목을 계산한다. RD가 올리면 영업사원은 본인 이름으로 저장된다.
5. 업로드 파일의 자동 계산 컬럼 값은 무시한다.
6. **양식 다운로드**: `/template`에서 빈 양식을 받는다(전화번호·현장번호 열은 텍스트 서식).

#### 4.5.1 목록
| 항목 | 사양 |

| 모바일 | 표 대신 카드 형태로 표시 |
| 상세 보기 | 행(모바일은 카드)을 **더블클릭**하거나 선택 후 Enter → 상세 팝업. 날짜·현장번호·고객명·영업사원·계약가·입출금·금액·입금구분·입금자·입금내용·입금처·현금영수증·비고·A/S·거래처 정보(공정·세부공정·업체·업체담당자·업체연락처·은행명·예금주·계좌번호·업체비고) 전체와 승인대기 상태를 표시하고, 하단에서 수정·삭제(권한에 따라)할 수 있다. 닫기 버튼·Esc·바깥 영역 클릭으로 닫는다 |

#### 4.5.2 검색
| 조건 | 방식 |
|---|---|
| 입출금 | 전체 / 입금 / 출금 버튼 |
| 현장번호 | 본인(관리자는 진행 중인 전체) 현장 목록에서 선택 또는 입력, 포함 검색 |
| 고객명, 입금자 | 포함 검색 |
| 영업사원 | 데이터에 있는 값 드롭다운 |
| 입금구분 | 입금구분 목록(5.3) + 데이터에만 있는 값 드롭다운 |
| 날짜 | 시작일 ~ 종료일 (한쪽만 입력 가능, 기간 검색 시 날짜 해석 불가 행 제외) |
| 초기화 | 모든 조건 해제 |

조건은 입력 즉시 적용되며 여러 조건은 AND로 결합된다. 조건이 바뀌면 1페이지로 이동한다.

#### 4.5.3 입금 등록·수정 창
**+ 입금 등록** 버튼 또는 행의 **수정** 버튼으로 연다. 저장 버튼은 **승인 요청**이다.

| 항목 | 필수 | 입력 방식 / 규칙 |
|---|---|---|
| 현장번호 | ✔ | 내 현장(현장정보.영업사원 = 로그인 이름) 목록에서 선택. CEO·관리자는 진행 중(완료일 없음)인 전체 현장에서 선택. 해당 목록이 없으면 직접 입력. 현장정보에 있는 번호면 고객명·영업사원 자동 채움 |
| 고객명, 영업사원 | | 텍스트 (RD는 영업사원 본인 이름 고정) |
| 입금구분 | ✔ | 5.3의 14개 중 선택. 고른 값으로 입출금·입금내용·입금자가 정해진다 |
| 입금/출금 | 조건부 | `홈씨씨창호`일 때만 표시, 입금 또는 출금 중 필수 선택 |
| 금액 | ✔ | 0보다 큰 숫자. 포커스가 빠지면 천 단위 쉼표 |
| 날짜 | ✔ | 기본값 오늘 |
| 입금내용 | 조건부 | `한샘 외 시공비`·`거래처환불`일 때만 직접 입력(필수), 그 외는 입금구분 값으로 자동 |
| 거래처 | 조건부 | `거래처환불`일 때만 입력(필수) → 입금자로 저장 |
| 현금영수증 | | **수정 화면에서만** 발행완료 / 발급필요 / 카드결제 선택. 고르지 않으면 기존 값 유지 |
| 비고 | | 여러 줄 텍스트, 500자 이내. 화면 이름만 "비고"이고 입금내역의 `A/S` 컬럼에 저장 (기존 `비고` 컬럼은 화면에서 받지 않음) |
| 거래처 정보 | 조건부 | `한샘 외 시공비`일 때만 필수(그 외 구분은 선택, 등록 후 **지우기** 가능). **+ 거래처 정보 등록** 버튼 → 거래처 선택 팝업(아래). 선택 후에는 공정·업체·담당자·연락처·주요작업·업체비고 요약과 **변경** 버튼을 보여준다. 필수인데 등록하지 않으면 승인 요청 불가 |

**거래처 선택 팝업**
1. **공정**: 공정표의 `공정`을 `순서`대로 보여주는 선택 목록(공정별 거래처 건수 표시). 고르면 공정표의 주요 작업을 안내한다.
2. **거래처**: 공정별거래처에서 `공정`이 같은 행을 모두 카드로 보여준다(업체, 담당자 성함·직책, 연락처, 구분, 세부 업무, 업체비고, 계좌, 계좌 사용 구분). 목록 맨 아래에 **직접 입력** 항목이 항상 있다.
3. **요약**: 거래처를 고르면 입금내역에 저장될 값을 공정 / 세부공정 / 업체 / 업체담당자 이름 / 업체담당자 연락처 / 은행명 / 예금주 / 계좌번호 / 업체비고로 보여준다. 이 중 **업체담당자 이름·연락처·은행명·예금주·계좌번호**는 값이 없어도 칸을 보여주고 입력·수정할 수 있다(공정별거래처 원본은 바뀌지 않음). **선택**을 누르면 입금 창에 반영된다.
4. **직접 입력**: 해당 업체가 목록에 없으면 직접 입력을 고르고 공정 외 모든 칸(업체 필수)을 입력한다(세부공정은 공정표의 주요 작업으로 미리 채움). 공정은 1단계에서 고른 값. **입력 완료**로 반영한다.

| 화면 이름 | 저장 컬럼 (입금내역) | 목록에서 고른 경우 |
|---|---|---|
| 공정 | 공정 | 고른 공정 |
| 세부공정 | 주요작업 | 거래처의 세부 업무 (비어 있으면 공정표의 주요 작업) |
| 업체 | 업체 | 업체 |
| 업체담당자 이름 ✎ | 업체담당자성함 | 업체담당자성함 |
| 업체담당자 연락처 ✎ | 업체담당자연락처 | 업체담당자연락처 |
| 은행명 ✎ | 업체은행 | 업체은행 |
| 예금주 ✎ | 업체예금주 | 업체예금주 |
| 계좌번호 ✎ | 업체계좌번호 | 업체계좌번호 |
| 업체비고 | 업체비고 | 업체비고 |

✎ = 목록에서 고른 경우에도 입력·수정 가능

- 입금 창에는 같은 형식의 요약과 **변경** 버튼을 보여준다. Esc·취소·바깥 클릭은 팝업만 닫는다.
- 수정 화면에서 다시 열면 기존 값이 공정별거래처에 있으면 그 행을, 없으면 직접 입력(기존 값 채움)을 미리 선택한다. 공정표에 없는 예전 공정명은 "현재 값"으로 남긴다.

- 화면 하단에 저장될 입금자 미리보기를 보여준다(입금자는 서버에서 최종 결정, 5.3).
- 수정 시 화면에서 받지 않는 계약가·입금처·비고는 기존 값을 유지한다. 바뀐 내용이 없으면 "변경된 내용이 없습니다"로 거부한다.
- 이전 형식의 입금구분(한샘/시공비/거래처환불입금 등) 행을 수정할 때는 기존 값을 안내한다.
- 요청 후 "승인 요청했습니다. 승인 후 입금내역에 반영됩니다" 안내를 띄운다.

#### 4.5.4 입금 삭제 (CEO·관리자)
- 확인 창 후 **승인 절차 없이 즉시 삭제**한다(삭제하는 사람이 승인 권한자이므로).
- 삭제한 행이 `한샘 외 시공비`·`거래처환불`이면 해당 현장의 자동 계산 항목을 다시 계산한다.

#### 4.5.5 엑셀 내보내기
현재 검색 결과 전체(모든 페이지)를 `입금내역_YYYYMMDD.xlsx`로 저장한다. 금액은 숫자, 날짜는 엑셀 날짜로 변환한다.

### 4.6 입금 승인 절차

입금내역의 등록·수정은 `승인필요입금내역` 테이블에 **승인대기** 요청으로 먼저 저장되고, CEO·관리자가 승인해야 `입금내역`에 반영된다.

```
[요청자] 등록·수정 요청 ──▶ 승인대기 ──(승인)──▶ 승인 : 입금내역에 반영 + 자동 계산
                               │
                            (반려 + 의견)
                               ▼
                              반려 ──(고쳐서 다시 요청)──▶ 승인대기
                               │
                            (요청자가 삭제) ──▶ 요청 행 삭제 (입금내역 변화 없음)
```

| 요청구분 | 승인 시 처리 |
|---|---|
| 등록 | 입금내역에 새 행 입력 |
| 수정 | `입금내역id` 행을 요청 내용으로 변경 |
| 삭제 | `입금내역id` 행 삭제 (요청 행에는 삭제 당시 내용을 복사해 둔다) |

- 승인 후 요청 내용과 변경 전 값 양쪽의 현장에 대해 자동 계산 항목을 다시 계산한다.
- 대상 입금내역이 이미 삭제된 수정·삭제 요청은 반영할 수 없다고 안내하고, 반려하도록 한다.
- 이미 처리된 요청을 다시 승인·반려하면 "이미 처리되었거나 찾을 수 없는 요청입니다"로 거부한다.
- 현재 화면에서는 삭제를 관리자가 즉시 처리하므로 새 '삭제' 요청은 만들어지지 않는다. 기존 삭제 요청은 위 규칙대로 처리된다.

#### 4.6.1 입금 승인 화면 (`/approvals`, CEO·관리자)
- 승인 대기 요청을 카드로 나열한다: 요청구분, 요청자 이름, 요청일시(한국 시간), 요청 내용, 수정·삭제 요청은 대상 입금내역의 현재 값.
- 재요청된 건은 이전 반려 의견을 함께 표시한다.
- **승인**: 확인 창 후 처리. **반려**: 반려 의견 입력 필수(500자 이내), `관리자의견`에 저장.

#### 4.6.2 내 승인 요청 화면 (`/my-requests`)
- 로그인한 사람이 요청한(`요청자` = 권한.id) 건 중 **승인대기**(보기 전용)와 **반려** 건을 보여준다.
- 반려 건: 관리자 의견(반려 사유)을 보여주고 다음 중 하나를 할 수 있다.
  - **고쳐서 다시 요청**: 입금 창을 열어 수정 후 같은 요청 행을 승인대기로 되돌린다. 삭제 요청 반려 건은 내용 없이 그대로 다시 요청한다(CEO·관리자만).
  - **삭제**: 다시 요청하지 않을 반려 건을 목록에서 지운다(입금내역은 바뀌지 않음).

### 4.7 나의정보 화면 (`/me`)
| 영역 | 내용 |
|---|---|
| 내 정보 | 영업사원ID, 이름, 역할, 최근 로그인, 승인 권한(CEO·관리자만 표시) |
| 비밀번호 변경 | 현재 비밀번호 + 새 비밀번호 + 확인 (3.3) |
| 내 현장 요약 | 전체 현장(진행·완료 건수), 진행 중 계약가 합계, 올해 계약 건수·금액, 미정산 건수(전체 계약가) |
| 입금 요약 | 내 입금내역의 입금 합계 · 출금 합계 |
| 내 요청 | 승인 대기·반려 건수 → `/my-requests` |
| 진행 중인 현장 | 최근 계약일 순 최대 10건 (현장번호, 고객명 등) → 현장정보로 이동 |

'내 현장·입금'은 역할과 상관없이 `영업사원` 컬럼이 내 이름인 행만 집계한다.

### 4.8 게시판 (`/board`)

#### 4.8.1 목록
| 항목 | 사양 |
|---|---|
| 표시 컬럼 | 번호, 제목(첨부 개수), 작성자, 작성일, 조회 |
| 공지 | 공지 글(최대 20건)은 검색·페이지와 관계없이 목록 위에 고정 |
| 정렬 | 최신 글 순 (id 내림차순) |
| 검색 | 검색 대상(제목+내용 / 제목 / 작성자) + 검색어. 서버에서 검색 |
| 페이징 | 15건 단위, 현재 페이지 주변 최대 10개 페이지 번호 |
| 모바일 | 표 대신 목록 형태로 표시 |

#### 4.8.2 글쓰기·수정·삭제 권한
| 동작 | 권한 |
|---|---|
| 글쓰기 | 로그인 사용자 전체 |
| 수정·삭제 | 작성자 본인 또는 CEO·관리자 |
| 공지 지정 | CEO·관리자만 (그 외 사용자가 수정해도 공지 여부는 유지) |

- 제목 필수 200자 이내, 내용 필수 20,000자 이내.
- 글을 삭제하면 첨부파일 정보와 실제 파일도 함께 삭제된다.

#### 4.8.3 첨부파일
| 항목 | 제한 |
|---|---|
| 파일 하나 | 10MB 이하 |
| 한 번에 올리는 합계 | 20MB 이하 |
| 글당 개수 | 10개 이하 |
| 차단 확장자 | .exe .bat .cmd .com .msi .ps1 .vbs .js .jar .scr .sh |

- 실제 파일은 서버의 `upload/` 폴더에 임의 이름(UUID)으로 저장하고, 원본 파일명·크기·형식은 `게시판첨부` 테이블에 저장한다.
- `upload/`는 public 밖에 있어 주소로 직접 접근할 수 없다. 로그인 확인 후 `/board/files/[fileId]`로만 내려받는다(원본 파일명으로 저장).
- 수정 화면에서 기존 첨부를 골라 지우고 새 파일을 추가할 수 있다.
- 첨부 저장에 실패하면 글도 남기지 않는다.

#### 4.8.4 글 보기
- 제목, 작성자, 작성·수정일시, 조회수, 내용, 첨부 목록(다운로드 링크).
- 글을 열 때 조회수를 1 올린다(DB 함수 `게시판_조회수_증가`). 본인 글을 볼 때는 올리지 않는다.

### 4.9 지식자산 (`/knowledge`)

공사 진행에 필요한 거래처·공정 정보를 조회하고 고치는 화면이다. 로그인한 사용자는 역할과 관계없이 모두 조회·추가·수정·삭제할 수 있다.

#### 4.9.1 탭
| 탭 | 주소 | 테이블 | 정렬 |
|---|---|---|---|
| 공정별거래처 (기본) | `/knowledge` | 공정별거래처 | id 오름차순 |
| 타공정거래처 | `/knowledge?tab=others` | 타공정거래처 | id 오름차순 |
| 공정표 | `/knowledge?tab=schedule` | 공정표 | 순서 오름차순(빈 값은 뒤) → id |

#### 4.9.2 목록
| 항목 | 사양 |
|---|---|
| 표시 컬럼 | 해당 테이블의 모든 업무 컬럼 (5.4.x). 컬럼이 많으면 가로 스크롤, 머리글 고정 |
| 셀 표시 | 최대 2줄, 넘치면 마우스를 올려 전체 내용 확인 |
| 검색 | 검색창 1개. 모든 컬럼에서 포함 검색, 띄어 쓴 여러 단어는 모두 포함된 행만 (화면에서 즉시 적용) |
| 공정 필터 | 데이터에 있는 `공정` 값 드롭다운 |
| 건수 | 전체 N건, 검색 중이면 `검색 결과 / 전체` |
| 페이징 | 없음 (테이블당 최대 5,000행 조회) |

#### 4.9.3 추가·수정·삭제
- **+ 추가**: 빈 입력 창을 연다. 공정 필터가 선택되어 있으면 `공정`에 그 값을 미리 채운다.
- **행 클릭**(또는 Enter/Space): 해당 행의 수정 창을 연다. 창에서 **저장** / **삭제**(확인 창 후 즉시 삭제, 되돌릴 수 없음) / **취소**.
- 저장 규칙
  - 앞뒤 공백을 제거하고 빈 값은 NULL로 저장한다.
  - `공정표.순서`는 정수만 허용(쉼표 허용), 그 외 컬럼은 텍스트.
  - 한 컬럼 2,000자 이내, 모든 칸이 비어 있으면 저장 불가.
  - `src/lib/knowledge-shared.ts`에 정의된 컬럼만 저장하고, 그 밖의 값은 무시한다.
- 저장·삭제 후 목록이 다시 읽히고, 검색 조건은 유지된다.

### 4.9.1 대시보드 (`/dashboard`, CEO·관리자)
- 대상: 진행 중인 현장(현장정보.완료일이 없는 현장) 전체. 권한이 없으면 첫 화면으로 이동한다.
- 표: 가로 = **시공비 · 한샘 · 홈씨씨 · 합계**, 세로 = 현장마다 **계약금 · 입금 · 출금 · 미입금** 4행(현장 칸에 고객명, 현장번호 · 영업사원).
  - 계약금 = 현장정보의 시공비 / 한샘상품가액 / 홈씨씨상품가액 (비어 있으면 `-`, 합계에서는 0)
  - 입금·출금 = 그 현장번호의 입금내역을 입금구분으로 묶어 합산 (현장 상세 입금내역의 표와 같은 규칙, `src/lib/site-money.ts`): 시공비 = 계약금1·2·착수금1·2·중도금1~3·잔금1·2(입금)와 한샘 외 시공비(출금), 한샘 = 한샘물대·한샘시공비, 홈씨씨 = 홈씨씨창호. 거래처환불·예전 형식 구분 제외.
  - 미입금 = 계약금 − 입금 (계약금이 비어 있으면 0으로 계산, 입금이 더 많으면 빨간색 "초과 금액")
- 맨 아래 **합산** 7행은 화면 아래에 고정된다.
  - 계약금 · 입금 · 출금 · 미입금: 진행 중 현장 합계
  - **예상공사비** = 합산 계약금 × 비율. 비율은 항목(시공비·한샘·홈씨씨)별로 화면에서 고칠 수 있고 기본 85%(빈 칸도 85%, 0~200%, 소수 둘째 자리까지). 원 단위 반올림. 저장하지 않으며 새로고침하면 85%로 돌아간다
  - **통장잔고**: 시공비·한샘·홈씨씨별로 화면에서 직접 입력하는 값. DB에 저장하거나 불러오지 않으며, 새로고침하면 비워진다. 빈 칸은 0, 음수 가능
  - **미입금 + 통장잔고 − 예상공사비**: 입력하는 즉시 다시 계산 (음수는 빨간색, 양수는 초록색)

### 4.10 공통: 오류 표시
- DB 연결·조회 실패 시 화면에 빨간 안내 상자로 원인을 표시한다.
- Server Action 실패는 해당 창 하단에 오류 문구를 표시한다(여러 오류는 줄 단위).

### 4.11 공통: 페이징 (현장정보·입금내역)
- 목록은 한 페이지에 **100건**을 표시한다.
- 하단에 `총 N건 중 a–b`와 페이지 버튼(« ‹ 번호 › »)을 표시한다. 페이지가 많으면 처음·끝·현재 주변만 보이고 나머지는 `…`로 줄인다.
- 페이지 이동 시 목록이 맨 위로 스크롤된다.
- 페이징은 화면에서 수행하며, 서버는 전체 데이터를 1,000행 단위로 나눠 모두 읽는다(Supabase 1회 응답 최대 1,000행 제한 대응).

## 5. 업무 규칙

### 5.1 자동 계산 항목

| 현장정보 컬럼 | 원천 테이블 | 조건 | 합계 대상 |
|---|---|---|---|
| 한샘공급가합계 | 한샘주문진도정보 | `계약현장번호` = 현장번호, `주문상태` = '확정' | `공급가` |
| 한샘물대 | 한샘주문진도정보 | 위와 같음 | `공급가(HS)` |
| 한샘시공비 | 한샘주문진도정보 | 위와 같음 | `공급가(S1)` |
| 한샘시공비외 | 입금내역 | `현장번호` 일치, `입금구분` = **'한샘 외 시공비'** (입출금 무관) | `입금액` |
| 환불금액 | 입금내역 | `현장번호` 일치, `입금구분` = **'거래처환불'** | `입금액` |

- 원천 금액은 텍스트(예: `"3,928,790"`)이므로 숫자로 변환해 더한다. 숫자로 읽을 수 없는 값은 합계에서 제외하고 상세 패널에 경고를 표시한다.
- 해당 행이 없으면 0으로 저장한다.
- `임시주문`, `취소` 주문은 합계에서 제외된다.
- 계산 결과가 저장된 값과 다를 때만 테이블을 갱신한다.
- 0.1의 입금구분 `시공비`·`거래처환불입금`으로 저장된 기존 행은 합계에 포함되지 않는다(5.3 참고).

**재계산 시점**

| 시점 | 대상 |
|---|---|
| 상세 패널 열기 | 해당 현장 |
| 현장 저장·신규 등록 (현장번호 변경 포함) | 해당 현장 |
| 엑셀 업로드 등록 | 등록된 현장 전체 |
| 입금 요청 승인 (등록·수정·삭제) | 요청 내용과 변경 전 값의 현장번호 |
| 관리자 입금 삭제 | 삭제한 행의 현장번호 |

> 한샘주문진도정보나 입금내역이 앱 밖에서 바뀐 경우, 현장정보 테이블 값은 해당 현장의 상세 패널을 열 때 갱신된다.

### 5.3 입금구분 규칙 (`src/lib/deposits.ts`)

입금구분을 고르면 입출금·입금내용·입금자가 아래처럼 정해진다. 입금구분 값은 그대로 `입금구분` 컬럼에 저장된다.

| 입금구분 | 입출금 | 입금내용 | 입금자 |
|---|---|---|---|
| 한샘물대 | 입금 | 한샘물대 | 현장정보의 고객명 |
| 한샘시공비 | 입금 | 한샘시공비 | 현장정보의 고객명 |
| 홈씨씨창호 | **화면에서 입금/출금 선택 (필수)** | 홈씨씨창호 | 현장정보의 고객명 |
| 한샘 외 시공비 | **출금** | 직접 입력 | `나비지급` |
| 거래처환불 | 입금 | 직접 입력 | 입력한 거래처명 |
| 계약금1, 계약금2 | 입금 | 입금구분과 같음 | 현장정보의 고객명 |

- '현장정보의 고객명'은 현장번호로 현장정보를 찾아 그 고객명을 쓰고, 없으면 화면에 입력한 고객명을 쓴다.
- 이전 형식의 값은 화면에서 다음과 같이 해석한다: `시공비` → 한샘 외 시공비, `거래처환불입금` → 거래처환불, `한샘` + 입금내용 `한샘물대`/`한샘시공비` → 해당 구분.

### 5.4 입금내역 저장 형식
입금내역 테이블은 id를 제외한 모든 컬럼이 text이므로, 기존 데이터와 같은 형식으로 저장한다.

| 항목 | 저장 형식 | 예 |
|---|---|---|
| 입금액, 계약가 | 천 단위 쉼표 문자열 | `1,480,000` |
| 날짜 | `YYYY년 MM월 DD일` | `2026년 11월 05일` |
| 현금영수증 | `발행완료` / `발급필요` / `카드결제` (예전 표기: `발행` → 발행완료, `미발행`·`미발급` → 발급필요로 해석) | |

검증 규칙: 현장번호 필수, 입금구분은 5.3 목록 중 하나, 금액은 0보다 큰 숫자, 날짜 필수·유효, 조건부 필수(입금내용·거래처), A/S 500자 이내, 거래처 정보는 `한샘 외 시공비`일 때 필수(공정·업체).

## 7. 서버 기능

모든 Server Action은 첫 줄에서 `authorizeAction()`으로 로그인을 확인하고, 입력을 서버에서 다시 검증·변환한 뒤 저장한다. 결과는 `{ ok: true, data }` 또는 `{ ok: false, error }` 형식으로 반환한다(로그인 관련 액션은 폼 상태를 반환).

### 7.1 로그인 (`src/app/auth-actions.ts`)

| 함수 | 기능 |
|---|---|
| `loginAction` | 로그인, 세션 시작, 접속시간 기록 |
| `changePasswordAction` | 최초 접속 비밀번호 변경 |
| `changeMyPasswordAction` | 나의정보 비밀번호 변경 (현재 비밀번호 확인) |
| `logoutAction` | 세션 종료 |

### 7.2 현장정보·입금내역·승인 (`src/app/actions.ts`)

| 함수 | 권한 | 기능 |
|---|---|---|
| `listSitesAction()` | 전체 (범위 적용) | 현장정보 조회 |
| `createSiteAction(values)` | 전체 | 현장 신규 등록 (영업사원 자동) → 자동 계산 |
| `updateSiteAction(id, values)` | 전체 (범위 적용) | 현장 수정 → 자동 계산 (자동 계산 컬럼은 입력값 무시) |
| `syncSiteTotalsAction(id)` | 전체 (범위 적용) | 자동 계산 항목 재계산·저장, 경고 반환 |
| `listComputedSourcesAction(현장번호, 필드)` | 전체 (범위 적용) | 자동 계산 항목의 근거 행 조회 |
| `listDepositsAction(현장번호)` | 전체 (범위 적용) | 현장별 입금내역 조회 |
| `createDepositAction(values)` | 전체 | 입금 **등록 요청** |
| `updateDepositAction(id, values)` | 전체 (범위 적용) | 입금 **수정 요청** (대기 중 요청이 있으면 거부) |
| `deleteDepositAction(id)` | CEO·관리자 | 입금 즉시 삭제 → 자동 계산 |
| `approveRequestAction(requestId)` | CEO·관리자 | 요청 승인 → 입금내역 반영 → 자동 계산 |
| `rejectRequestAction(requestId, comment)` | CEO·관리자 | 요청 반려 (의견 필수) |
| `resubmitRequestAction(requestId, values)` | 요청자 본인 | 반려 건 수정 후 재요청 |
| `deleteRejectedRequestAction(requestId)` | 요청자 본인 | 반려 건 삭제 |
| `parseExcelAction(formData)` | 전체 | 업로드 파일 해석, 미리보기 반환 (저장하지 않음) |
| `insertSitesAction(rows)` | 전체 | 업로드 선택 행 일괄 등록 → 자동 계산 |

### 7.3 게시판 (`src/app/board-actions.ts`)

| 함수 | 권한 | 기능 |
|---|---|---|
| `createPostAction(form)` | 전체 | 글 + 첨부 저장 (공지는 관리자만) |
| `updatePostAction(id, form)` | 작성자·관리자 | 글 수정, 첨부 추가·삭제 |
| `deletePostAction(id)` | 작성자·관리자 | 글·첨부 정보·실제 파일 삭제 |

### 7.4 지식자산 (`src/app/knowledge-actions.ts`)

| 함수 | 권한 | 기능 |
|---|---|---|
| `saveKnowledgeRowAction(tableKey, id, values)` | 전체 | id가 null이면 추가, 있으면 수정 |
| `deleteKnowledgeRowAction(tableKey, id)` | 전체 | 행 삭제 |

`tableKey`는 `vendors` / `others` / `schedule` 중 하나만 허용한다(그 외는 거부).

### 7.5 Route Handler
| 경로 | 메서드 | 기능 |
|---|---|---|
| `/template` | GET | 엑셀 업로드 양식 다운로드 (요청 시 생성, 컬럼은 현장정보 필드 정의를 따름) |
| `/board/files/[fileId]` | GET | 로그인 확인 후 게시판 첨부파일 다운로드 (원본 파일명) |

### 7.6 주요 설정 (`next.config.ts`)
- `cacheComponents: true`, `partialPrefetching: true`
- `experimental.serverActions.bodySizeLimit: "21mb"` (엑셀 업로드 5MB, 게시판 첨부 한 번에 합계 20MB 수용)
- `experimental.proxyClientMaxBodySize: "21mb"` (proxy가 업로드 본문을 자르지 않도록)

## 8. 환경 설정 및 실행

### 8.1 환경 변수 (`.env.local`, git 제외)

| 변수 | 용도 | 노출 범위 |
|---|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | Supabase 프로젝트 URL | 브라우저 노출 가능 |
| `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` | 공개 키 (현재 앱에서는 미사용) | 브라우저 노출 가능 |
| `SUPABASE_SECRET_KEY` | 서버 전용 키 (RLS 우회) | **서버 전용, 절대 노출 금지** |
| `AUTH_SECRET` | 세션 쿠키 서명 키 (32자 이상) | **서버 전용, 절대 노출 금지** |

- Supabase 설정이 없으면 "`.env.local`에 NEXT_PUBLIC_SUPABASE_URL과 SUPABASE_SECRET_KEY를 설정한 뒤 개발 서버를 다시 시작하세요" 안내가 표시된다.
- `AUTH_SECRET`이 없거나 32자 미만이면 로그인할 수 없다는 안내가 표시된다. 바꾸면 모든 사용자가 다시 로그인해야 한다.

### 8.2 실행 명령

| 명령 | 설명 |
|---|---|
| `npm install` | 의존성 설치 |
| `npm run dev` | 개발 서버 (http://localhost:3000) |
| `npm run build` | 프로덕션 빌드 |
| `npm start` | 빌드 결과 실행 |
| `npm run lint` | 코드 검사 |

### 8.3 배포 시 확인 사항
- 환경 변수 4개를 호스팅 환경에 설정한다.
- 게시판 첨부파일은 서버 디스크 `upload/` 폴더에 저장되므로, **디스크가 유지되는 서버**에서 실행하고 이 폴더를 백업 대상에 포함한다(서버리스 환경에서는 파일이 사라진다).
- `doc/`의 DB 변경 스크립트(6.8)가 운영 DB에 모두 적용되었는지 확인한다.

### 8.4 개발 도구 연동
Claude Code에 Supabase MCP 서버(`supabase`, 원격 HTTP)가 로컬 범위로 등록되어 있다. 대상은 위 프로젝트 하나로 제한되며 쓰기 권한이 있다. 설정은 사용자 홈의 `.claude.json`에 저장되고 저장소에는 포함되지 않는다.

## 9. 보안 및 제약 사항

| 구분 | 내용 | 권장 조치 |
|---|---|---|
| 비밀번호 평문 저장 | `권한.비번`이 평문이라 DB 접근 권한이 있는 사람은 모든 비밀번호를 볼 수 있다. 로그인 실패 횟수 제한도 없다. | 해시 저장으로 전환하고 관리자 초기화 기능 추가, 로그인 시도 제한 검토 |
| 지식자산 수정 권한 | 로그인한 모든 사용자(RD 포함)가 거래처 계좌 정보를 수정·삭제할 수 있고, 변경 이력이 남지 않는다. | 필요 시 CEO·관리자만 수정 가능하도록 제한, 변경 이력 테이블 검토 |
| 관리자 즉시 삭제 | CEO·관리자의 입금 삭제는 승인 없이 바로 반영되고 되돌릴 수 없다. | 필요 시 삭제 이력 보관 |
| 역할 변경 반영 | 역할·이름은 로그인 시점 값으로 12시간 유지된다. | 권한 회수 시 `AUTH_SECRET` 교체 또는 다시 로그인 안내 |
| 키 노출 이력 | 개발 중 Supabase access token과 secret key가 대화에 노출되었다. | 두 키 재발급 후 기존 키 폐기 (`.env.local`, MCP 설정 갱신) |
| 현장번호 중복 허용 | 현장번호 단독 UNIQUE 제약이 없다. 업로드 시 화면에서만 중복을 경고한다. | 필요 시 현장번호 UNIQUE 제약 추가 검토 |
| 이전 입금구분 데이터 | 0.1 형식(`시공비`, `거래처환불입금`, `한샘`)으로 저장된 행은 자동 계산 합계에 포함되지 않는다. | 해당 행의 입금구분을 새 값으로 일괄 변경 |
| 자동 계산 시점 | 원천 데이터가 앱 밖에서 바뀌면 상세 패널을 열기 전까지 저장값이 이전 값으로 남는다. | 항상 최신이어야 하면 DB 트리거로 계산 이전 검토 |
| 대량 데이터 | 현장정보·입금내역 목록은 전체 데이터를 받아 화면에서 페이징한다. 수만 건 이상이면 느려질 수 있다. | 규모 증가 시 서버 페이징·서버 검색으로 전환 |
| 첨부파일 저장 위치 | 서버 디스크에 저장되어 서버 교체·재배포 시 유실될 수 있다. | 백업, 또는 Supabase Storage로 이전 검토 |
| 데이터 미연결 | 입금내역의 현장번호 `이천현장`은 현장정보에 없는 번호로, 어느 현장에도 표시되지 않는다. | 데이터 정리 |
